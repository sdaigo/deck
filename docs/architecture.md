## アーキテクチャパターン

### レイヤードアーキテクチャ

```
┌──────────────────────────────────────────┐
│   UIレイヤー (React Components)           │ ← ユーザー入力の受付と表示
│   App, TodoInput, TodoList, TodoItem,     │
│   TodoFilter, Toast, ErrorFallback        │
├──────────────────────────────────────────┤
│   状態管理レイヤー (Custom Hooks)          │ ← ビジネスロジック・状態管理
│   useTodos, useToast                      │
├──────────────────────────────────────────┤
│   データレイヤー (Storage Adapter)         │ ← データ永続化
│   todoStorage                             │
└──────────────────────────────────────────┘
         │
         ▼
   ┌────────────┐
   │ localStorage │
   └────────────┘
```

#### UI レイヤー
- **責務**: ユーザー入力の受付、バリデーション表示、結果のレンダリング
- **許可される操作**: 状態管理レイヤー（hooks）の呼び出し
- **禁止される操作**: データレイヤーへの直接アクセス、localStorage の直接操作

#### 状態管理レイヤー
- **責務**: Todo の CRUD ロジック、フィルタリング、通知管理、ストレージ同期
- **許可される操作**: データレイヤーの呼び出し
- **禁止される操作**: DOM 操作、UI レイヤーへの依存

#### データレイヤー
- **責務**: localStorage への読み書き、データバリデーション、シリアライゼーション
- **許可される操作**: localStorage API へのアクセス
- **禁止される操作**: ビジネスロジックの実装、React hooks の使用

### 依存関係の方向

```
UI → 状態管理 → データ (OK)
UI → データ (NG)
状態管理 → UI (NG)
データ → 状態管理 (NG)
```

## データ永続化戦略

### ストレージ方式

| データ種別 | ストレージ | フォーマット | 理由 |
|-----------|----------|-------------|------|
| Todo リスト | localStorage | JSON | サーバー不要。5MB の容量は Todo データに十分。同期的 API でシンプル |

### ストレージキーとスキーマ

- キー: `simpletodo:data`
- スキーマバージョニング: `version` フィールドで将来のマイグレーションに対応

```typescript
type StorageSchema = {
  readonly todos: ReadonlyArray<Todo>;
  readonly version: number;
};
```

### バックアップ戦略

- **方式**: なし（MVP スコープ）
- **理由**: localStorage はブラウザローカルのデータであり、ユーザー自身がデータの所有者。クリアされた場合はゼロから再開
- **将来の拡張**: Export/Import 機能（JSON ファイル）を Post-MVP で検討

## パフォーマンス要件

### レスポンスタイム

| 操作 | 目標時間 | 測定方法 |
|------|---------|---------|
| 初回ロード（LCP） | 1 秒以内 | Lighthouse Performance（キャッシュなし、高速回線） |
| タスク追加 | 100ms 以内 | React DevTools Profiler（状態更新 + 再レンダリング） |
| タスク完了トグル | 100ms 以内 | React DevTools Profiler |
| タスク削除 | 100ms 以内 | React DevTools Profiler |
| フィルター切り替え | 50ms 以内 | React DevTools Profiler |

### リソース使用量

| リソース | 上限 | 理由 |
|---------|------|------|
| バンドルサイズ（gzip） | 50KB 以下 | 1 秒以内のロードを実現するため |
| localStorage 使用量 | 1MB 以下 | ブラウザの 5MB 制限に対して十分なマージン。Todo 1 件あたり約 200 バイトで 5,000 件相当 |

## セキュリティアーキテクチャ

### データ保護

- **暗号化**: なし（ローカルデータのため。機密情報は扱わない）
- **アクセス制御**: ブラウザの Same-Origin Policy に依存
- **機密情報管理**: 機密情報を扱わないため該当なし

### 入力検証

- **バリデーション**: タスクタイトルの長さ制限（1-200 文字）、空文字チェック、前後空白トリム
- **サニタイゼーション**: React の JSX エスケープ機構に依存。`dangerouslySetInnerHTML` は使用禁止
- **ストレージバリデーション**: localStorage 読み込み時に JSON パース + スキーマ検証。不正データはフォールバック処理

### Content Security Policy

Vite のビルド設定で以下の CSP ヘッダーを index.html に設定:

```
default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'
```

`unsafe-inline` は Tailwind CSS のインラインスタイルに必要。外部スクリプト・リソースの読み込みは禁止。

## スケーラビリティ設計

### データ増加への対応

- **想定データ量**: 最大 5,000 件（localStorage 1MB 以内）
- **パフォーマンス劣化対策**: React.memo + useMemo によるレンダリング最適化。100 件までは描画遅延なし
- **アーカイブ戦略**: MVP ではなし。Post-MVP で完了済みタスクの一括削除機能を検討

### 機能拡張性

- **プラグインシステム**: なし（MVP スコープ外）
- **コンポーネント分離**: 各コンポーネントが単一責務を持ち、独立してテスト・置換可能
- **ストレージ抽象化**: `todoStorage` の interface を通じてストレージ実装を差し替え可能（将来的に IndexedDB やサーバー API に変更可能）

## テスト戦略

### ユニットテスト

- **フレームワーク**: Vitest
- **対象**: todoStorage（load/save/バリデーション）、useTodos（CRUD/フィルタリング）、useToast（通知管理）
- **カバレッジ目標**: 80% 以上

### 統合テスト

- **フレームワーク**: Vitest + Testing Library
- **対象**: コンポーネント間の連携（入力 → 状態更新 → 表示、エラー → Toast 通知）
- **方法**: renderHook + fireEvent でユーザー操作をシミュレート

### E2E テスト

- **ツール**: Playwright
- **シナリオ**: タスク CRUD の一連フロー、ページリロード後のデータ永続化、フィルター切り替え、Error Boundary の動作確認
- **ブラウザ**: Chromium（CI 環境。ローカルでは全ブラウザ対応を手動確認）

## 技術的制約

### 環境要件

- **対応ブラウザ**: Chrome, Firefox, Safari, Edge の最新版
- **必須ブラウザ API**: localStorage, crypto.randomUUID()
- **必要な外部依存**: なし（サーバー不要、完全クライアントサイド）

### パフォーマンス制約

- localStorage の同期的 API はメインスレッドをブロックする。大量データの読み書き時に UI が固まる可能性があるが、想定データ量（5,000 件以下）では問題にならない
- crypto.randomUUID() は一部の古いブラウザで非対応。対象ブラウザ（最新版）では全て対応済み

### セキュリティ制約

- localStorage のデータはブラウザの DevTools から閲覧・編集可能。機密データの保存には使用しない
- Same-Origin Policy により他ドメインからのアクセスは防止されるが、同一ドメイン上の他スクリプトからはアクセス可能

## 依存関係管理

| ライブラリ | 用途 | バージョン管理方針 |
|-----------|------|-----------------|
| react | UI ライブラリ | `^19.0.0`（メジャー固定） |
| react-dom | DOM レンダリング | `^19.0.0`（react と同期） |
| tailwindcss | スタイリング | `^4.0.0`（メジャー固定） |
| vite | ビルドツール | `^6.0.0`（メジャー固定） |
| typescript | 型チェック | `~5.7.0`（パッチのみ自動） |
| vitest | テスト | `^3.0.0`（メジャー固定） |
| @testing-library/react | DOM テスト | `^16.0.0`（メジャー固定） |
| playwright | E2E テスト | `^1.0.0`（マイナー自動） |
| @biomejs/biome | Lint + Format | `^2.0.0`（メジャー固定） |

**方針**:
- 本番依存（react, tailwindcss）: メジャー固定、マイナーバージョンまで自動更新
- 開発依存（vitest, biome 等）: メジャー固定、マイナーバージョンまで自動更新
- TypeScript: パッチバージョンのみ自動（型チェックの挙動変化を最小化）
