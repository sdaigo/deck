# ワークフロールール

## 基本フロー

1. `docs/` で「何を作るか」を定義
2. `.steering/` で「今回何をするか」を計画
3. tasklist.md に従って実装、進捗を随時更新
4. テストと動作確認
5. 必要に応じてドキュメント更新

## Do's

- 既存ドキュメントの内容を最優先する
- 成果物はユーザーの明示的な承認を得てから次に進む
- 出力したコードやドキュメントに「不備やリスクがないか」を3点指摘してから提出する
- 大量のファイル読み込み・修正が必要な作業はサブエージェントに委譲する
- メインコンテキストではファイル内容の Read を最小限にとどめる（修正箇所が分かっている場合は offset/limit で絞る）

## Don'ts

- 独自の用語を作らない
- コンテキスト不明な状態で推測のみで仕様決定しない
- メインコンテキストで大量のファイルを逐次 Read -> Edit しない（サブエージェントに委譲する）
- 1件ずつ逐次処理で修正しない（関連する修正はグループ化してバッチ実行する）

## スキル共通ルール

- 新規作成時はスキルのテンプレートとガイドを参照
- 更新時は既存の構造と内容を維持

作業中にプロセスの不備を発見したら、直ちにドキュメントを更新する。
