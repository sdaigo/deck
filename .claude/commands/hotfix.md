# ホットフィックス

引数: `/hotfix [修正内容の簡潔な説明]`

## 対象

- typo、設定値の修正、1-2行の緊急修正
- 新しい設計判断を伴わないもの
- 変更ファイルが1-3個程度

**判断基準**: 修正内容を1文で説明できなければ `/patch` を検討する。

## ステップ1: 準備

1. コンテキストを確立する:
   - 修正名: `$ARGUMENTS` から簡潔な名前を生成（例: `fix-typo-header`）
   - 日付: `[現在の日付をYYYYMMDD形式で取得]`
   - ステアリングディレクトリ: `.steering/[日付]-hotfix-[修正名]/`
2. ステアリングディレクトリを作成する
3. `hotfix/[修正名]` ブランチを作成する

## ステップ2: changeset.md を作成

`.steering/[日付]-hotfix-[修正名]/changeset.md` を以下のテンプレートで作成する:

```markdown
# Hotfix: [修正内容]

- 日付: [YYYY-MM-DD]
- タイプ: hotfix
- ブランチ: hotfix/[修正名]

## 変更理由

[なぜこの修正が必要か。1-2文で]

## 影響範囲

[変更するファイルと影響を受ける箇所]

## 完了チェック

- [ ] 修正完了
- [ ] テスト通過
- [ ] レビュー通過
```

## ステップ3: 修正の実施

1. 対象ファイルを特定し修正する
2. changeset.md の「影響範囲」を実際の変更内容で更新する

## ステップ4: レビューとテスト

以下を**並行起動**する:

- code-reviewer (sonnet): hotfix レビュー。変更が最小限かつ副作用がないことを重点確認
- test-runner (haiku): 変更に関連するテストを優先実行

レビュー指摘・テスト失敗があれば修正する。

## ステップ5: 完了

1. changeset.md の完了チェックを更新する
2. 変更ファイルと changeset.md をコミットする（`fix: [修正内容]`）
3. ユーザーに完了を報告し、マージ方法を確認する
